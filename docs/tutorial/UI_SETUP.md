# UI Setup - Example TODO App

## Main UI login

The `main.rs` contains the UI setup.
It contains:

### State
The state is a struct that is shared through the whole app

It doesn't need to have any traits (`Clone`, `Debug`, ...). The only requirement is that it needs to be generated from a function

See [App\<GuiState\>](../user-guide/APP_STATE.md)

### Window Params
The window params are a set of parameters that are passed to your code when a window wants to create another window, you then process these datas so you can create the correct window in the correct state

See [WindowParams](../user-guide/WINDOW_PARAMS.md)



## Create Window function
This function is charged to create the windows from the Window Params.

Signature:
```rust
fn create_window(params: WindowParams, state: &mut App<GuiState>, win_id: WindowId) -> Window;
```

This takes a params, the App, and a window id.

Definitions:
- [WindowParams](../user-guide/WINDOW_PARAMS.md)
- [App\<GuiState\>](../user-guide/APP_STATE.md)
- [WindowId](../user-guide/WINDOW_ID.md)


See [create_window](../user-guide/CREATE_WINDOW_FN.md)

## window_manager! macro
This macro will create the necessary setup to manage multiple windows

It is constituted of:
- A windows list
- The `GuiState` type
- The `WindowParams` type

This will generate:
- A `Window` enum
- A `DEFAULT_ENGINE_SETTINGS` constant
- Some functions that you shouldn't touch

Example:
```rust
window_manager!(Window {
    HomeWindow,
    ErrorWindow,
    TasksWindow,
    SettingsWindow,
    StartupWindow,
    ResultsWindow,
    DetailsWindow,
    AiChatWindow
}; GuiState; WindowParams);
```

## And for our TODO App?

Reminder:
We want two windows:
- `TodoListWindow`
- `TodoDetailWindow`

We want, as params:
- Pass the Window Type (as enum)
- Pass the task ID, if `TodoDetailWindow`

### 0. The Task
We will just create a simple struct `Task`

Code (`task.rs`):
```rust
pub struct Task {
    pub name: String,
    pub description: String,
    pub done: bool,
}
```

### 1. The State
We want the TODO list to be inside of the state, so we can fetch it from `TodoDetailWindow`

The Task list will be a `Vec<Task>`

Code (add to `task.rs`):
```rust
pub type Tasks = Vec<Task>;
```

Code (`state.rs`):
```rust
use crate::task::Tasks;

pub struct AppState {
    pub tasks: Tasks,
}
```

### 2. Window Params
We will use a struct, that will contain an enum.

The enum will contain:
- `TodoListWindow`
- `TodoDetailWindow(task_id)`

Code (in `params.rs`):
```rust
#[derive(Clone)]
pub enum WindowType {
    TodoListWindow,
    TodoDetailWindow(usize)
}

#[derive(Clone)]
pub struct WindowParams {
    pub window: WindowType
}
```

### 3. Create Window function
We want to pass the state in a `init` function on both windows.

We also pass the informations (in the TodoDetailWindow's case it's the task id) directly in the `new()` method

So we need:
```rust
pub fn create_window(params: WindowParams, state: &mut App<AppState>, _win_id: WindowId) -> Window {
    match params.window {
        WindowType::TodoListWindow => {
            let mut win = TodoListWindow::new();

            win.init(state);

            Window::TodoListWindow(win)
        }
        WindowType::TodoDetailWindow(task_id) => {
            let mut win = TodoDetailWindow::new(task_id);

            win.init(state);

            Window::TodoDetailWindow(win)
        }
    }
}
```

_Note: `Window` is auto-generated by the `window_manager!` macro and it looks like this:_
```rust
pub enum Window {
    TodoListWindow(TodoListWindow),
    TodoDetailWindow(TodoDetailWindow)
}
```

_Note (2): In a real application, you would handle Window creation errors at this level, new would return a `Result<T, E>`_

### 4. The `window_manager!` macro
We simply need to add the two windows into the macro, and give the types AppState and WindowParams.

It will look like this _(you can fix the import errors when we will add the windows)_

```rust
window_manager!(Window {
    TodoListWindow,
    TodoDetailWindow
}; AppState; WindowParams);
```
